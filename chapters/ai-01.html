案例 01：看不懂项目目录，怎么问#

导读

对应第二、四章。场景：刚下载解压，一堆文件不知从哪看起。

❌ 低效问法#

text
这个项目文件太多了，每个是干嘛的？

为什么不好：没给目录结构，AI 只能凭"一般项目的常识"猜，给你的大概率是"index.html 是入口、style.css 是样式"这种你已经知道的废话。

✅ 改进问法#

text
我下载了一个 GitHub 开源任务管理器项目，目录如下：

index.html / style.css / script.js / taskUtils.js /
script.test.js / package.json / package-lock.json /
eslint.config.js / .prettierrc / README.md / LICENSE /
CONTRIBUTING.md / .github/workflows/ci.yml

我学过一点 HTML 和 JavaScript 基础，但没接触过 Node。
请告诉我：
1. 浏览器真正运行时需要哪几个文件？
2. package.json、eslint.config.js 这类文件，不装 Node 能跑吗？
3. 我该按什么顺序读这几个核心文件来理解项目？

好在哪里：给了完整文件列表（上下文）、交代了自身水平（约束）、问的是三个具体问题（期望形式）。

AI 示范回答 · 教学构造，非真实记录
说明

运行只需要 4 个：index.html、style.css、script.js、taskUtils.js。其中 index.html 是入口，末尾用 type="module" 引入 script.js，script.js 再 import taskUtils.js。其余文件是开发工具配置（package.json 管 npm 脚本、eslint 管代码风格、ci.yml 管自动检查），不装 Node 也能跑页面。建议读码顺序：index.html（看结构）→ taskUtils.js（短，看工具函数）→ script.js（主体，挑着看）。

核实清单：AI 说了不算，逐条验证
  • AI 说"入口是 index.html"——自己打开确认末尾有 <script type="module" src="script.js">；
  • AI 说"不需要 package.json"——把项目复制到没装 Node 的环境真能跑；
  • AI 说"script.js import taskUtils.js"——去 script.js 顶部看 import 语句核实。

进一步追问（拿到答案后）#

text
确认了 4 个核心文件。请再帮我用一句话概括
index.html、script.js、taskUtils.js 各自的职责分工。

——为第四章"分清 HTML/CSS/JS 职责"铺垫。
