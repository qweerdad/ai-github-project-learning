第一章：AI时代，我们应该怎样学习编程项目？#

说明

本章约 30 分钟，以阅读和讨论为主，不需要写代码。

学习目标#

学完本章，你应该能用自己的话回答：

  1. 为什么不需要"先把所有技术学完"才能开始做项目；
  2. AI 在工程项目里能帮你做什么、不能替你做主什么；
  3. 哪些基础能力仍然必须自己掌握；
  4. 为什么不能无条件相信 AI 给的答案；
  5. 这门课结束时你要具备什么能力。

开始前需要#

  • 会用浏览器上网、会解压压缩包；
  • 见过代码（C、Python 或其他语言），看得懂"函数""变量"这些词；
  • 有一个能用的 AI 聊天工具（任何一个都行，免费版足够）。

1.1 一个真实的困惑#

很多同学的学习路径是这样的：

text
学语法 → 做练习题 → 学完"下一门课" → 再学"下下一门课" → ……迟迟不敢碰真实项目

问题在于：真实项目永远不会等到你"准备好了"才出现。一个只有几百行代码的 GitHub 项目，里面也可能同时出现你没学过的语法、没听过的 API、看不懂的英文注释和陌生的文件组织方式。如果标准是"全部看懂才能动"，那永远动不了。

这门课换一个标准：

说明

先让项目跑起来，再在项目里按需学习。

我们会用一个真实的 GitHub 开源项目（一个叫 TaskFlow 的网页任务管理器），从头到尾走完这条路线：

text
看懂项目是干什么的 → 下载 → 跑起来 → 借助 AI 读懂结构
→ 提一个自己的需求 → 借助 AI 小步修改 → 亲自测试验证 → 能向别人解释你做了什么

注意中间有两步是"借助 AI"，而首尾全是"你自己"。这就是本课的态度。

1.2 AI 在这件事里能做什么#

下面这件事，两种做法对比一下：

任务：给任务管理器加一个"任务备注"功能。

  • 没有 AI 的做法：先学 HTML/CSS/JavaScript 的系统课程 → 学 DOM API → 学 localStorage → 读完全部源码 → 才敢动手。周期以"月"计。
  • 有 AI 的做法：先让项目跑起来 → 让 AI 帮你定位"任务数据结构在哪个文件""渲染列表的是哪个函数" → 你只改需要的几处 → 自己测试。周期以"天"甚至"小时"计。

AI 像一个随时在线的师兄：你给它看代码片段，它能解释；你说目标，它能给方案；你贴报错，它能猜原因。这在真实工程里已经是常态工作方式——本课教的就是这套方式，而不是教某个 AI 的魔法指令。

1.3 但 AI 帮不了的事，恰恰是你要学的事#

AI 适合承担 你必须亲自承担
解释一段陌生代码 描述"我到底想要什么"
猜测哪个文件可能相关 判断 AI 的解释是否符合代码事实
给出一版修改草案 理解关键数据和逻辑怎么流动
解释报错信息的可能原因 运行程序、检查修改是否真的生效
帮忙列出测试思路 区分"证据"和"猜测"，决定是否采纳建议
整理文档 向别人讲清楚你改了什么、为什么这么改

划重点三条：

① AI 会一本正经地犯错。 它可能编造不存在的函数名、引用你项目里没有的文件、给出"看起来对"但跑不通的方案。本课程第五、六章会给你看一个真实例子：AI 声称某段逻辑由某函数处理，而源码里根本没有那个函数。判断它对不对，靠的是证据（代码、运行结果），不是信心。

② "AI 写的代码能跑" ≠ "你学会了"。 如果你说不清哪一行做了什么、为什么放这个文件里，那这份代码不属于你。所以本课每个练习都要求你用自己的话解释修改——这才是你的能力。

③ 跑起来 ≠ 改对了。 新功能能用，不代表老功能没被改坏；正常输入能过，不代表边界输入不崩。第七章专门练这个。

1.4 哪些基本功仍然要自己学#

AI 时代不是"不用学基础"，而是"按需学基础"。本项目里你会实际需要（不需要精通，需要看得懂）：

  • HTML 是骨架：页面上有什么元素（输入框、按钮、列表）；
  • CSS 是皮肤：它们长什么样（颜色、间距、动画）；
  • JavaScript 是肌肉：点击后发生什么（改数据、改页面）；
  • 数据与界面分离：任务真正存放在一个叫 tasks 的数组里，页面只是数组的"投影"；
  • localStorage：浏览器自带的简单仓库，让任务刷新后不丢；
  • 开发者工具（DevTools）：浏览器里按 F12 打开，能看报错、看数据、看元素。

这些都会在第三、四章结合真实代码讲，不懂的概念随时问 AI——但问过之后要自己验证一遍。

1.5 本课程的最终能力目标#

课程结束时，你应该能独立完成下面这串事（第八章的练习就是照这个标准出的）：

  1. 打开一个陌生 GitHub 仓库，判断它适不适合自己；
  2. 不用 Git 也能把代码下载下来，并找到正确的版本；
  3. 用免费工具把它跑起来，认出"跑起来了"和"看起来跑了其实没跑"；
  4. 借助 AI 读懂目录结构和一条完整的数据流；
  5. 提出一个小需求，让 AI 辅助你完成局部修改；
  6. 用开发者工具和测试验证修改，发现 AI 的错误；
  7. 向别人讲清楚：项目干什么、入口在哪、你改了什么、怎么验证的。

这些能力可以直接迁移到竞赛入门、课程设计、科研训练和你自己的第一个"像样"的项目。

本章 AI 提问示例#

下面这些问题现在就可以拿去问你的 AI，感受一下"怎么问"的差别（第五章会系统讲）：

  • 低效：「教我学前端。」（太大，AI 会给你一篇读不完的教科书）

  • 改进：「我在读一个 HTML/CSS/JS 写的任务管理器源码，看到 localStorage.setItem('taskflow_tasks', ...)，请用三句话告诉我 localStorage 是什么、数据存在哪、什么时候会丢。」

  • 低效：「这个函数干嘛的？」（没贴代码，AI 只能猜）

  • 改进：把函数原文贴上去，加一句「这是任务管理器项目里 taskUtils.js 的函数，请逐行解释，并指出哪一行负责转义 HTML。」

自检问题 · 勾选状态仅保存在你的浏览器
  • 我能说出"先在项目里跑起来再按需学"和"系统学完再碰项目"的区别；
  • 我能各举出 3 件"AI 适合做"和"我必须自己做"的事；
  • 我知道 AI 可能犯什么类型的错误（编造函数、猜错原因）；
  • 我同意课程结束时需要"用自己的话解释我的修改"。
过关标准

能向同学（或对空气）完整复述 1.5 节的七条能力目标，并且说得出本课用的是哪个开源项目、为什么选它。答不上来的，回到对应小节再看一遍。
