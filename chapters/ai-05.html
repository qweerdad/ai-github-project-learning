案例 05：AI 给了大段重写，怎么要求缩小范围#

导读

对应第五、六章。场景：你问个小改动，AI 甩给你整个重写过的文件。

典型情况#

你问"怎么让搜索也能搜备注"，AI 回了 600 行的完整 script.js，说"替换掉原来的就行"。

为什么危险：

  • 你不可能逐行审完 600 行；
  • AI 可能顺手"优化"了别处、改了你没让改的逻辑；
  • diff 巨大 = 出错点多 = 回归风险大；
  • 整文件粘贴 = 放弃学习。

✅ 应对追问#

text
这个改动太大了，替换整文件我审不过来。
请只给最小改动：
1. 列出要改的函数名，每个函数里加/改哪几行；
2. 用"修改前 → 修改后"的片段形式给，别整文件；
3. 哪些原有行为可能受影响，我重点回归测什么？
AI 示范回答 · 教学构造，非真实记录
说明

只需改 filterTasks 一处（taskUtils.js 第 32~37 行）：

text
- return tasks.filter((t) => t.text.toLowerCase().includes(q));
+ return tasks.filter((t) => t.text.toLowerCase().includes(q)
+     || (t.note || '').toLowerCase().includes(q));

script.js 不用动。要回归的：原本只搜文字的行为不能变（搜不到备注的旧任务仍按文字搜）；搜索为空时要显示全部。

核实清单：AI 说了不算，逐条验证

把 AI 给的"修改前"片段，和你文件里的真实代码逐字对比：

  • AI 给的"修改前"是 t.text.toLowerCase().includes(q)——打开 taskUtils.js 第 35 行核对，一字不差才说明 AI 是基于你的真实代码在改；
  • 如果"修改前"和你文件里的不一样——AI 在凭记忆/通例猜你的代码。这时把真实代码贴给它："我文件里实际是 XX，请基于这个重改。"

配套动作：用 diff 验证它到底改了多少#

改完后跑：

bash
git diff --no-index 原版文件 改后文件

如果 AI 说"只改一行"而 diff 显示改了几十行——它偷偷动了别处，逐处审查再决定保不保留。

红线#

任何"帮你顺手重构了""顺便优化了""统一了风格"的整文件输出，默认不接受。你要的是"改这一处"，不是"把整个文件变一个样"。
