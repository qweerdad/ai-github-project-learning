练习 C：换一个陌生项目，走完全流程#

导读

难度：挑战 ｜ 预计 2~4 小时或更久 ｜ 对应第八章 8.4 这一关没有教程领路——它才是"真学会"的证明。哪怕没做完，走通前五步就是大收获。

任务#

在 GitHub 上自己找一个纯 HTML/CSS/JS 的小项目，对它有针对性地完成一次小修改，并产出一份"我做了什么"的报告。

怎么找项目（关键词建议）#

GitHub 搜索栏试这些组合，挑 star 几百以内、README 清晰的小项目：

  • vanilla javascript todo
  • vanilla javascript timer / pomodoro
  • vanilla javascript quiz
  • vanilla javascript notes / calculator / expense tracker

避开：需要后端/API key 的、用 React/Vue 构建的（起步太难）、文件多到数不清的。

你要做的事（对照教程的五步）#

  1. 评估（第二章方法）：它干什么/什么技术/能不能浏览器跑/LICENSE 是什么/适不适合你。写 5 行结论；
  2. 复现（第三章）：Download ZIP → 本地服务器 → 跑起来 → DevTools 确认没报错；
  3. 读懂（第四章）：找入口、追一条数据流（比如"提交/添加一次发生了什么"）、画出和 TaskFlow 类似的四层图；
  4. 定需求 + 改（第五、六章）：给自己定一个小功能 → 让 AI 给方案 → 小步改；
  5. 验证（第七章）：三层手动测试 + diff 留证据。

产出要求：一页报告#

写不超过一页，必须包含（每条都要有具体细节，不许空话）：

  • 项目名 + 仓库地址 + LICENSE；
  • 它是干什么的（一两句）；
  • 入口文件、数据存在哪；
  • 我加的功能 + 动了哪几个文件；
  • AI 帮了我哪几处、我亲自验证/纠正了哪几处；
  • 我的测试证据（哪几项、结果）；
  • 如果再改一个功能，我会从哪开始。

防卡指南#

卡在哪 回去看
项目选不准 2.3 评估速查表
跑不起来 3.2 file:// 坑、3.3 服务器、7.x DevTools
代码读不动 第四章读码顺序
AI 给的东西不敢用 第五章核实方法
改完不知道对不对 第七章三层验证

评分参考（自评/师评）#

  • 报告每条都有具体细节（函数名/字段名/文件名），不是"我改了一些代码"这种话；
  • 能现场打开项目指出改动的那几行；
  • 测试不是"我试了没问题"，而是"我做了 X 操作预期 Y 得到 Z"。

这一关的意义：课程带你走完了 TaskFlow，但真实世界里没有教程陪你走第二个项目——能离开教程做，才算把方法变成自己的。
