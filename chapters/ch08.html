第八章：从跟着教程操作，到独立解决下一个问题#

要点

本章约 2~4 小时（含练习）。检验标准不是"你看完了"，而是"你能离开教程做"。

学习目标#

  1. 在少量提示下完成一个新的小修改；
  2. 独立分析需求并借助 AI 完成一个功能扩展；
  3. 面对陌生项目能走通全套方法（评估→跑起来→读懂→改→验证→解释）；
  4. 把本课程沉淀成你自己的"下一个项目学习流程"。

开始前需要#

  • 前七章全部过关；
  • 保留好你的 TaskFlow-任务备注版（对照基准）。

8.1 迁移的本质：方法不变，对象变了#

前七章你做的事，每一步都是可迁移的通用动作：

你做过的事 通用方法
看 README/LICENSE/commits 判断适不适合 项目评估速查表
ZIP 下载/解压/跑本地服务器 通用复现路径
file:// 打不开 → 找 type="module" → 上服务器 "先怀疑运行方式"的排查直觉
追"添加任务"这条线 追一条用户操作看数据流
带上下文问 AI、验证 AI 说的函数 上下文提问 + 证据核查
加备注字段贯穿 4 文件 一个字段要贯穿 数据/UI/存储/测试
三层验证 + 回归清单 能跑/功能对/没改坏
diff 留证据 任何修改都要可对照、可还原

换一个项目，这套流程原封不动再走一遍。 变的只是具体的技术细节。

8.2 练习 A（入门）：小修改，有提示#

剧透警告

对应侧栏「学生练习」组的练习A 筛选按钮页。这里只给任务，参考答案在侧栏 ⚠ 标记的「参考答案」组。

任务：给任务列表加一个"只显示高优先级任务"的筛选按钮。

提示（先看提示再想，别直接翻答案）：

  • 筛选逻辑在 filterTasks(tasks, filter, searchQuery)，目前 filter 只有 all/active/completed；
  • HTML 里筛选按钮在 <div class="filters">，照抄一个按钮改 data-filter；
  • JS 里 setFilter 负责切换；
  • 任务对象的 priority 字段值是 'high'/'medium'/'low'。

验收标准：点新按钮只显示 high 优先级任务；其他筛选不受影响；刷新后仍在当前筛选。

8.3 练习 B（进阶）：独立需求 + AI 辅助#

说明

对应侧栏「学生练习」组的练习B 相对时间页。

任务：给每条任务显示"已创建多久"（如 "2 hours ago"、"3 days ago"）。

要求：

  1. 先自己写需求（边界：超过 7 天显示完整日期还是保持 "7 days ago"？自己定）；
  2. 用第五章的方法让 AI 给方案（不要先要代码）；
  3. 提示：需要一个"相对时间格式化"函数——往 taskUtils.js 里放，还是 script.js？想清楚为什么（纯函数 → taskUtils）；
  4. 参考 formatDueDate 的写法（它就在 taskUtils 里）；
  5. createdAt 字段已经存在，直接用；
  6. 做完用 7.2 的方法手动测 + 加单元测试。

考察点：能不能把"需要一个工具函数"归到对的位置、能不能用 AI 的方案而不是被 AI 的方案带着走。

8.4 练习 C（挑战）：换一个真实项目，走全流程#

说明

对应侧栏「学生练习」组的练习C 迁移项目页。

任务：在 GitHub 上自己找一个纯 HTML/CSS/JS 的小项目（建议关键词：vanilla javascript + todo/timer/quiz/notes），走一遍：

  1. 评估：用 2.3 的速查表判断适不适合；
  2. 复现：ZIP 下载 + 本地服务器跑起来；
  3. 读懂：找到入口、追一条数据流（比如"提交一次"）；
  4. 提需求：给自己定一个小功能；
  5. 借助 AI 完成：先要方案再小步改；
  6. 验证：手动测三层 + diff 留证据；
  7. 写一份"我做了什么"报告（见 8.5）。

这一关的意义：教程里你是被带着走的，这一关没有教程——只有方法。如果你卡在某一步，回看对应章节：卡评估看 2.3，卡运行看 3.2/3.3，卡读码看第四章，卡提问看第五章，卡验证看第七章。

热身建议：进练习 C 之前，先做侧栏里的练习D 按需学习——就在 TaskFlow 本项目内，练"遇到不认识的写法就地学懂"的四步流程（观察→提问→验证→笔记）。练习 C 里你会大量用到它。

8.5 结业输出：一份"我能讲清楚"的报告#

三个练习做完（至少做完 A 和 B，C 尽力），写一份不超过一页的报告，回答：

  1. 原项目是干什么的？（一两句话）
  2. 入口文件是哪个？数据存在哪？
  3. 我加了什么功能？动了哪几个文件？
  4. AI 帮了我什么？我亲自验证了什么？
  5. 我怎么确定改对了？（测试与验证）
  6. 如果再加一个功能，我会从哪里开始？

评分标准（自评/互评）：每一条都有具体细节（函数名、字段名、文件名），不是空话。说不清的那条，就是你还没真正掌握的那一环——回去补对应章节。

8.6 沉淀：你的"下一个 GitHub 项目"流程卡#

把这张卡片存下来，以后遇到任何开源项目按它走：

text
□ 看 README：干什么/什么技术/怎么跑
□ 看 LICENSE：能不能复制修改（MIT/Apache/BSD 可以）
□ 看规模：核心源码我数得过来吗
□ 拿代码：Download ZIP（固定版本优先）或 git clone
□ 找入口：index.html / main.xxx / package.json 的 main
□ 跑起来：本地服务器/npm/按 README
□ 追一条线：一个操作从输入到存储的完整链路
□ 定个小需求：一句话说清要什么
□ 先要 AI 方案：动哪几个文件/有什么坑
□ 小步改：照抄项目现有风格，不整文件重写
□ 三层验证：能跑/功能对/没改坏
□ diff 留证据：能说清每一处改动
□ 能讲给别人听：入口/数据流/我改了什么/怎么验的

本章 AI 提问示例（迁移场景）#

  • 「这是一个用 jQuery 写的旧项目（贴某文件），我想用本教程的方法改造它。请先告诉我：它的入口在哪、数据怎么存的、和你见过的现代 JS 项目最大的区别是什么。」
  • 「我找到一个项目（贴 README），帮我按"技术栈/依赖/规模/改进空间"评估适不适合新手二次开发。」
  • 「这个项目和我上一个做的 TaskFlow 结构不同（贴目录），帮我找它的"init"入口和"数据存储"在哪。」
自检问题 · 勾选状态仅保存在你的浏览器
  • 我能不看教程说出"评估→复现→读懂→改→验"五步法；
  • 我能解释为什么"一个字段要贯穿多层"；
  • 我完成了至少练习 A 和 B，试了 C；
  • 我写完了 8.5 的报告且每条都有细节。
过关标准

独立完成练习 C 并产出 8.5 报告。报告的每一条都能被追问出细节——比如你说"加了功能"，别人问"哪一行代码？"你能立刻打开指出来。能讲清楚，才算真学会。
